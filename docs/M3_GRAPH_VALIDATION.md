# M3 第二部分：导图处理进度与显式补建

版本 `0.1.0-desktop-preview.8`，2026-10-23。本页记录实际实现与验证范围，最终安装产物另行登记。

## 行为

- 当前会议处于复习模式时，可读取持久原文总数、确认处理数、未确认数、忙闲与本运行时最近错误。状态读取、打开与恢复会议不会自动请求模型。
- 明确点击后按当前问答模型补建，每次最多 8 批；每批为 `MINDMAP_MIN_SEGMENTS` 限制在 1–32，每批最多 3 次逻辑尝试，失败间隔 200/400ms。当前真实 LLM 适配器每次最多 2 次 HTTP 尝试，因此一批最多可达 6 次 HTTP；本次回归用模拟模型，不调用付费服务。
- 新表 `mindmap_processed_segments` 以会议和原文 ID 为主键；图、操作日志、处理进度一次事务提交。合法空结果代表已处理，不承诺每句话都有节点；重复补建只读取尚未成功的原文。
- 显式补建中任一非法/不可应用操作导致整批失败；实时处理保留原有丢弃非法、提交合法操作的约定。实时部分失败通过现有操作日志中的 `incomplete_batch` 留存，原文仍未确认处理；已落合法节点的再次补建须接受重复风险。合法空结果才可以确认无节点的成功处理。不修改原有断言来掩盖行为变化。
- 结束采集后取消实时订阅，保留显式补建能力；切会话和退出关闭 writer，取消退避，忽略迟到结果与旧错误。当前 LLM 接口没有取消信号，在途 HTTP 可继续到返回或配置超时；不宣称已取消远端请求。不会接管 STT worker。
- 旧版或导入导图没有处理账本，不能从节点推断全文覆盖。页面显示风险，接口要求明确 `allowUntracked:true`；再次处理可能重复或调整已有节点。导出仍可使用，但不携带本轮新增账本，再导入按未知进度处理。
