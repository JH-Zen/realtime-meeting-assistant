## 新 agent 如何加入

1. 为自己的任务复制 [TEMPLATE.md](TEMPLATE.md)，保存为 `docs/agent-logs/YYYY-MM-DD-版本/唯一agent名-任务.md`。先写任务、允许修改的文件、已有脏改动和状态“进行中”，再开始修改。
2. 只维护自己的记录。开工前与其他执行方划定文件范围；确需多人改同一文件时，由主 agent 串行集成。
3. 重要修改、验证失败、范围变化和完成时更新记录。明确区分“自己实现”“采用别人的草稿后集成”“只做审查”和“只观察到已有改动”。
4. 写明实际执行的检查、结果和可定位证据。引用别人的验证要写执行方；没有跑的检查明确写未执行。失败、待验收和限制都保留。
5. 完成后将记录链接加入本索引；并行期间索引由主 agent 统一更新，避免争改同一文件。记录应保存在工作区内，聊天输出和 `work/` 临时日志只能作为补充证据。

## 记录边界

- 不包含密钥、`.env` 内容、会议正文、录音、个人账号或安装备份。可以记录脱敏的配置项名称、文件位置、校验值与结果。
- 已交付记录保持历史事实；后续修正追加日期与原因，不把历史失败改成成功，不用当前模型名覆盖当时的实际模型。
- 文档记录本身不提升软件版本。产品功能或修复交付仍按根 `AGENTS.md` 提升版本、更新 CHANGELOG 和开发计划。
- `docs/releases/`、验证说明和输出目录中的报告记录版本整体结果；本目录记录每个参与者的职责、实际贡献与交接信息。
