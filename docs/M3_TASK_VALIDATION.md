版本 `0.1.0-desktop-preview.10`，2026-10-23。桌面基础已完成；M3整体与完整交付仍待完成。

## 本轮实现

- 复习模式中的手动索引和导图补建，在任何等待或模型工作之前先保存任务。连点共用同一个任务；没有缺失内容时不创建空任务。保留原有每次最多8批、每批最多3次逻辑尝试和200/400ms退避。
- SQLite增量增加 `recovery_tasks`。任务保存类别、时间、初始/结束时缺失数、完成批数，以及最多24条批次尝试的输入数/保存数/状态。任务不保存原文、提示词、模型输出、密钥或原始服务错误；失败原因只用固定代码。
- 页面增加“补建任务记录”，显示当前会议最近10次本机手动补建，展开查看每批尝试。读取、打开历史或重启都不自动触发补建。批次尝试数不是底层HTTP请求数；模型适配器可能自行重试。
- 终态区分已完成、达到批次上限仍待补建、失败、中断；保存终态后拒绝迟到写入。成功以结束时实际覆盖缺失为0判断，不代表模型内容准确。
- 切换会议/退出时同步取消并封存任务。独立测试发现第一次元数据写失败会留下“进行中”，现已修复：立即仅重试一次封存元数据，取消位持续阻止新模型工作和迟到结果。长期磁盘或数据库写失败仍无法保证记录落盘，页面报告保存故障；存储修复后重启会封存遗留任务。
- 后端启动时，在恢复任何runtime前一次性将所有遗留running任务/尝试标记为process_interrupted；不会由此自动恢复模型调用。新增只读接口 `/api/session/:id/recovery-tasks`，仅当前选中会议可读，错误会议409；仓库不可用或读取失败503，不能伪装为空的已知历史。
- 操作历史只属于本机数据库，不随会话JSON导出/导入；导入仍沿用原有的索引创建行为。旧版运行、实时生成、摘要/问答与补建之前的失败没有此历史，不能据空列表推断它们成功。

## 使用与限制

结束录音后，在“补建缺失索引”或“补建未处理导图”按需启动；随后展开“补建任务记录”。旧导图仍需接受原有重复/调整节点提示。记录中的完成数是处理状态，不能证明转写、导图或检索语义完整。

任务记录与业务写入不在同一个事务内；极端退出可能已经保存派生内容但任务仍标中断，应以实际覆盖状态核对。任务历史目前无自动清理或分页界面，仅最近10条可见，其余留在数据库。完整实时任务审计、自动恢复策略、I13旧浏览器启动器、真实设备/权限与十分钟真人质量验收仍待完成；本轮不声明真实STT或硬件通过。

开发 `npm run dev:desktop`，构建 `npm run build`，打包 `npm run package:desktop`。本轮为控制D盘空间，新staging/安装测试放C盘独立临时目录；正式旁路位置、用户配置与数据库位置沿用 [DESKTOP.md](DESKTOP.md)。不迁移旧安装数据，不发布远程，不下载模型。
