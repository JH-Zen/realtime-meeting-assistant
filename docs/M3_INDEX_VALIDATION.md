# M3 第一部分：显式检索索引补建

版本 `0.1.0-desktop-preview.6`。本轮同时建立 Qoder CLI 与 Codex/GPT 子 agent 的分工，过程见 [QODER_WORKFLOW.md](QODER_WORKFLOW.md)。

## 实施范围

- 结束录音或打开历史会议后，真实页面显示当前检索索引覆盖数、缺失数和补建按钮。
- 状态由已保存的最终转写与当前 embedding 提供方、维度可用的向量比较得到；刷新、重启仍能发现缺失。
- 手动补建一次最多处理 8 批，每批最多尝试 3 次，退避 200/400 毫秒。持续失败保留缺失与原因，恢复服务后可再次手动触发。
- 同一运行时的重复补建合并；只补缺失项，使用既有 SQLite 索引唯一约束防止重复。原文、导图和其他会议保持不变。
- 录音、暂停或结束整理期间拒绝补建；请求必须指定当前会议。会议切换与退出后停止后续重试并忽略迟到结果。
- 读取状态、打开历史不会自动请求 embedding；既有实时索引失败策略保持原有行为。补建使用应用当前 embedding 配置，真实提供方可能需要先启动或安装其既有运行环境。

## 验证方式

先构建 shared，再运行核心补建与真实 API 的故障回归；之后执行类型、lint、构建和必要回归。桌面验证脚本仅在自己创建的独立测试数据目录中移除一条派生向量，然后启动实际 Electron 页面，点击按钮，验证索引补齐、原文与导图一致以及错误会议 ID 被拒绝。不会修改真实用户库来制造故障。

打包前实际通过：48 个文件、373 项 Node 自动测试（其中新增核心补建/停止/数据库失败 17 项，接口集成 10 项）；shared 优先构建、全项目类型检查、构建与 lint 通过。lint 保留旧 `review-probes.ts` 的 12 个 warning 与 1 个 info，本轮新增代码未新增提示。

- 开发桌面 37 项：`D:\Apps\.rcc-desktop-verification\index-dev-preview6-20261023\verification.json`。包含真实 Electron 业务页、模拟转写/导图/问答、导入导出、重复启动、端口占用、失败页、关闭、虚拟文件采集与索引补建。虚拟音频上传测试没有执行真实识别。
- 浏览器入口 7 项：`D:\Apps\.rcc-browser-verification\index-preview6-20261023\verification.json`，包括 Vite、Cookie 引导、WS、跨源拒绝与重启重连。
- 正式安装、非空数据重装与实际旁路升级的结果随包保存在 `outputs/desktop-preview/v0.1.0-desktop-preview.6/` 的验证报告中。安装包与 SHA256 同目录保存。

Qoder 首轮生成草稿但非交互 `dont_ask` 拒绝写入，主 agent 从草稿审查接入；改用 `accept_edits` 的实际写入探针成功，后续代码和测试修正已由 Qoder 真正保存到独立副本，再经差异审查接入。GPT 子 agent 独立写接口测试并审查，发现的状态显示、停止边界及前端旧响应问题均已修正。原有测试断言保持不变。

## 未覆盖范围

- 本轮属于 I05 的索引补建基础；没有实现导图任务补建，也没有让实时失败批次自动持续重试。
- I06 的前端到后端、后端到 STT 两段音频缺口记录与时间轴仍待实施。补建向量不能恢复未保存的语音或原文。
- 不证明真实 embedding 的语义质量、真实 STT 准确率、真实麦克风/权限或十分钟真人连续识别。本轮不新增真实模型调用。
- 不改旧浏览器安装版的启动/停止脚本；不迁移旧会议数据，不发布远程版本。
