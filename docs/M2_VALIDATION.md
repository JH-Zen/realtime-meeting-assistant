# M2：结束后复习与本机会议恢复

日期：2026-10-23。桌面版本：`0.1.0-desktop-preview.4`。基于工作区已有桌面/M1/CPU STT 实现继续开发，未创建提交或发布远程版本。仅关闭开发计划的 I03/I04 基础问题，完整交付仍待完成。

## 使用方式

1. 录音时按“结束”，等待“正在收尾…”完成；设备停止，原文、导图和问答保留，可以继续提问或导出。
2. 展开“本机会议”，打开数据库中已保存的会议；有分页与刷新入口。录音/暂停时禁止切换，先结束当前采集。
3. “关闭会议”清空当前页面并取消自动恢复选择，数据库内容保留；可重新从列表打开。
4. 直接关闭窗口仍退出应用；下次启动恢复上次选中的已保存内容，不自动开启麦克风。异常退出留下的记录标为“未正常结束”，仅供查看，不伪装成已完成或可继续采集。

开发启动：`npm run dev:desktop`。构建：`npm run build`。通用本地打包：`npm run package:desktop`。需 Windows x64 和项目依赖；先构建 shared。用户程序目录、独立 Node 后端、权限与单实例边界沿用 [DESKTOP.md](DESKTOP.md)。

## 实现与数据兼容

- `RecordingController.finish()` 排空输入并停止导图代理，保留同一问答运行时；不会取消正在回答的问题。`stop()` 仍负责进程退出的完整清理，`closeSession()` 另行清除选择。
- `GET /api/sessions` 分页列出实际 SQLite 记录及原文/节点数量；`POST /api/session/:id/open` 按 ID 打开，无输入连接。导入过程中如有更新的选择或录音，不抢回界面；导入副本仍在列表中。
- `SessionRuntime` 用持久化 final 原文填充近期窗口，不重发原文事件、不重建导图或重复写入向量。索引建立/检索失败时，问答仍得到近期原文；这不保证超出窗口的久远内容可以找回。
- 连接或切换统一发送会议、导图、原文、已存问答四组有序快照；包含尚在回答与早前中断的问题。切换清空旧原文、临时字幕、问答、错误、节点坐标/折叠缓存和输入草稿。同一会议重连仍保留拖拽位置。
- 新流式答案及模块错误带会议 ID；前端拒绝旧会议迟到内容。新提问携带目标会议 ID，切换后的旧请求不会提交到新会议。保留旧客户端的协议兼容入口，不将其当作多用户隔离。
- 同一数据库新增 `workspace_state` 选择元数据和可空 `sessions.duration_sec`；无新数据库，无旧安装目录数据迁移。旧记录时长保持未知，新完成记录保存不计暂停的时长，JSON v1 可选携带该字段。
