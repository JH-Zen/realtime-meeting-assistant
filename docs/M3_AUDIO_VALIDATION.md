# M3 第三部分：音频缺口与采集时间轴

版本 `0.1.0-desktop-preview.9`，2026-10-23。桌面基础已完成，M3 整体和完整产品交付仍未完成。

## 本轮行为

- 新前端在后台确认录音后绑定会议和采集 ID，以实际 16k 样本数累加源时间。暂停/继续更换采集 ID，正常暂停不按丢包处理；上传失败仍递增序号与样本位置。PCM 不排队重放，前后端发送缓冲超过256KiB时拒绝新音频帧。
- 前端到后台检查缺头、缺序和结束报告中的尾部；重复、倒序、重叠、错会议和无效帧不送往 worker。新采集候选先完整验证，不能让非法候选淘汰仍在工作的采集。结束报告可在断线后补发，队列只留最多32份小型元数据，不留音频。
- 后台到 STT 按实际发出的 PCM 样本建立 worker 时钟到源时间的分段映射；前端间断、静音和 worker 重连不再只靠最后一句识别时间拼接。无 position 的旧协议仍可用，但不宣称具有相同的缺口/时间轴证据。
- `observed` 表示观察到帧未能进入下一链路或序号/源时间缺口；`possible` 表示断连中不确定的区间或已发送但无 final 处理边界的范围。final 不是传输ACK，也不是文字完整性证明。跨缺口的同一语句可有跨区间起止时间，缺口另列。
- 新增 SQLite `audio_gaps` 表；同链路/原因/确定性的相邻区间合并。状态读取不请求模型，页面显示当前会议的区间、持续时间和确定性；不把两段可能重叠的时长相加。
- 会话JSON在既有v1上增加可选 `audioGaps`，导入校验区间与会议归属，再按新会议ID保存。旧文件缺该字段仍能打开，页面一直提示“没有记录不代表完整”。旧阅读器可能忽略新字段；没有迁移旧安装版数据。
- 已完成/历史会议拒绝迟到采集结束报告，避免复习时篡改记录；正常结束的报告在暂停/结束命令前同步发送。应用退出或页面崩溃期间仍不能保证每份结束报告都持久化。

## 尚未解决

没有每帧送达/识别ACK，也没有音频重放与自动补录；内核/设备未产出样本、首帧前断线、页面崩溃失去结束报告等情况不能精确测量所有损失。已发送未final范围可能只是静音，故只标“可能”，不推断必有文字丢失。连续性记录不是硬件健康或识别质量证明。

真实设备、Windows实际权限、十分钟真人与真实模型准确率/长跑未验收。本轮无付费模型调用、无权重下载。后续优先做真人短录音/十分钟验收与延迟、重复字/术语评估，再完善任务审计和自动恢复策略。I13旧浏览器启动脚本仍单独待修复。

## 开发与协作

运行 `npm run dev:desktop`；构建 `npm run build`；后续升版后 `npm run package:desktop`。数据位置、进程退出与安全边界沿用 [DESKTOP.md](DESKTOP.md)。

Qoder任务可由主agent通过 `tools\qoder-interactive.cmd "<已准备的独立任务目录>" --run-task` 自动带入可见CMD并保持交互；不再要求用户每轮转发。启动时未终止旧会话；交付前旧进程已退出，原因未确认，新可见会话仍在。平台DeepSeek-Flash与1M已核实，reasoningEffort为null，未确认max。每位执行方记录见 [agent索引](agent-logs/README.md)。
